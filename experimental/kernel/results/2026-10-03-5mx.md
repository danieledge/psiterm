# PsiKernTest 0.2 on Dan's 5mx, 3 October 2026

The raw log is [`2026-10-03-5mx.log`](2026-10-03-5mx.log). Every step ended with `< step: 0`: no crash, and the palette was put back after each write.

Register meanings come from Symbian's `WINDMERE.INC` (via `psionEmulators/tests/windmere.inc`) and NetBSD's `windermerereg.h`. Psion's own Windermere specification was never published, so readings marked *probably* are not certain.

## The machine and the driver

- **Machine:** SERIES5mx, ROM 1.05(260), ARM 710T at 36864 kHz. RAM 16384 KB (9584 KB free), ROM 16384 KB.
- **Driver:** loads, opens, version 0.2. The CPU mode in the driver is `0x1b` (UND), as in the emulator, so it is how ER5 runs executive calls, not an emulator quirk.
- **Speed:**
  - Loop: 2,000,000 turns in 328 ms, about 6 CPU cycles a turn at 36.864 MHz. The CPU runs at its full clock from the cache.
  - Memory copy: 2 MB in 62 ms. The tick is 15.6 ms, so this is ±25%: a longer test is needed for a firm figure.

## Registers

| Register | Value | Meaning |
|---|---|---|
| `PWRCNT` | `00000004` | `Clkflg`: 36 MHz core clock (0 would be 18 MHz). There is no faster setting, so **no overclocking from software**. |
| `MEMCFG1` | `00925050` | One byte per chip select. CS0 and CS1 = `50`: 32-bit, **125 ns** access, sequential access on at 40 ns. These are probably the two 8 MB ROMs. CS2 = `92`: 8-bit, 125 ns, EXPCLK on. CS3 = `00`: 32-bit, 225 ns (probably unused). |
| `MEMCFG2` | `00009393` | CS4 and CS5 = `93`: PCMCIA mode, 125 ns, EXPCLK on (probably the CF slot). |
| `DRAMCFG` | `ffff0081` → `ff700081` | Refresh on, divide ratio 1, 32-bit DRAM. `Trpctrl` (RAS precharge one clock shorter) is **off**. The top half changed between the two reads, so those bits are live or undefined: never write them back as read. |
| `LCDDBAR1` | `c000d000` | The frame buffer's physical address. The palette is its first 32 bytes, and the pixels follow (virtual `58003000` / `58003020`). This **confirms the palette model on real hardware**. |
| `LCDT1` | `010108ef` | Low bits `0ef` = 239: 240 lines. |
| `LCDT0`, `LCDT2` | `01010a70`, `00000b0b` | Horizontal timing and probably the pixel-clock divider. They set the refresh rate. To be decoded before any change. |
| `UART2 UBRCR` | `00000003` | `UBRCR = 7372800 / (16 × rate) − 1`, so 3 = **115200**. **230400 is `UBRCR` 1**, and 460800 would be 0. (The 0.2 harness on the device labels this "UART2 LCR"; the source now says UBRCR.) |
| `UART2 FCR` | `00000070` | 8 data bits, FIFO on. |
| `UART2 CON` | `00000000` | The UART was off at the time: no app had COMM::0 open. |
| `PWRSR` | `31` → `1a` | Live power and status bits. They change on their own. |
| `TC2 LOAD` / `CTRL` | `2800` / `0f` | TC2 reloads at 10240, periodic. |
| `INTENS` | `000008ae` | The interrupts enabled. |

## The palette

The palette is `200e 000d … 0008 0007 0007 0006 … 0000`, exactly as in the emulator:
- 16-grey mode, with black at level 14;
- level 7 used twice;
- level 15 never used.

It passed the check. Invert and all six grey curves ran and were put back.

The log can't say how the curves *looked*: Dan's eye is the result.

## What this opens up, in order

1. **230400 serial.** The hardware divider allows it (`UBRCR` 1). Next harness test, read only: open COMM::0 at 115200, 57600 and 9600, and read `UBRCR` each time, to confirm the formula on this machine. Then a guarded write that allows only `UBRCR` 1 on an open port and restores it when the port closes, tried against the Atom set to 230400.
2. **Grey curve for the whole machine.** This depends on how the curves looked on the panel.
3. **ROM wait states** (CS0/1 at 125 ns, so 100 ns would be `Ac100`). Most of EPOC runs in place from ROM, so this would speed up the whole UI. If the ROM can't keep up, the machine hangs at once (the setting is lost on reset). This needs a write with a timed automatic undo, and the speed test before and after.
4. **DRAM `Trpctrl`.** One clock less RAS precharge, for faster RAM. The same risk class as 3, and the register's top bits must be preserved.
5. **Refresh rate** (`LCDT2`): after decoding.
