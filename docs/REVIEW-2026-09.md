# Robustness review, September 2026 (0.54 -> 0.55 on dev)

An independent review of PsiTerm's own code (app and psissh; Dropbear and
libvterm excluded) for error handling, edge cases and hangs.

Verdict: sound overall - file parsers are length-checked, the update path is
signature-gated, the two-process shared memory is correct, and the EIKON
lifecycle cases are handled. Found and fixed in 0.55:

| # | Severity | Issue | Fix |
|---|---|---|---|
| 1 | High | psissh spun at 100% CPU forever when the TCP connection closed in Psion Internet (PPP) mode; auto-reconnect never fired | psi_read returns EOF once the socket is closed |
| 2 | Medium | a saved host with a long user + host name overflowed a buffer on the start screen (crash at every launch) | larger buffer |
| 3 | Medium | a big paste on a slow link froze the UI and overwrote unread keystrokes | waits at most ~2 s, then drops the rest with a message; never overwrites |
| 4 | Medium | Stop during an update redialled up to 6 times; partial downloads were left on disk | Stop checked before each piece; partial file removed on every failure |
| 5 | Medium | a psissh left running by a crashed PsiTerm kept the serial port until reboot | the next launch asks it to quit first |
| 6 | Low | long update-server names could overflow psissh's message buffers | bounded formats |
| 7 | Low | long screenshot file names overflowed a header buffer | larger buffer |
| 8 | Low | settings, hosts, snippets and keys were rewritten in place (a flat battery mid-save lost them) | written to a temporary file, then swapped in |
| 10 | Low | TLS ServerHello parsing could read past its buffer on a malicious server | bounds checks |
| 12 | Low | Update / speed test sometimes showed an empty window instead of saying why | message added |

Not changed: blocking waits of a few seconds in hang-up and network writes
(#9), and a normal logout not calling the Psion session-end hook (#11, the
next dial copes).
